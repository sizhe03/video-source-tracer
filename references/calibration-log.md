# Calibration log — measured values behind every threshold

`evidence-levels.md` states the *contract*. This file records the **numbers the
contract was tuned on**, and — more importantly — which numbers are stale, which
came from a single fixture, and which were produced by an algorithm generation
that no longer exists.

Read this before re-deriving any threshold. A threshold without its provenance
is a guess that looks like a fact.

---

## 1. Audio fingerprint (`auprint.py`)

### Two generations of numbers coexist

| generation | hash construction | figures | applies to current code? |
|---|---|---|---|
| old | `(f1, f2)` | 25,441 / 2,353 / 1,262 votes | **NO** — that hash was replaced |
| current | `(f1, f2, dt)` | 38,794 vs 16,032 (true); 6,847 vs 6,730 (unrelated) | yes |

The `dt` term is the frame gap between the two peaks (Wang's original Shazam
construction). Without it, dense or periodic material collides with itself at
every offset and the histogram is flat for *true* matches too.

**Do not quote the old generation as calibration.** It describes code that no
longer exists.

### Thresholds and where they came from

| constant | value | basis | confidence |
|---|---|---|---|
| `CLUSTER_RADIUS` | 3 bins | `HOP/SR` = 512/8000 → ±0.192 s. A bin conversion, not a measured tolerance | derived, exact |
| `MIN_ANALYSED_SECONDS` | 8.0 | below this the lag histogram has too few frames to be stable | judged |
| `MIN_CLUSTER_ABSOLUTE` | 12 | one coincidence vote must not pass | judged |
| `MIN_HASH_YIELD` | 0.02 | too few independent landmarks below this | judged |
| `MIN_TIME_COVER` | 0.05 | a distribution can clear every other bar while matching <1 % of the timeline | judged |
| `MIN_PROMINENCE` | 1.6 | sits between measured unrelated (1.02) and true match (2.42) | one fixture |
| `TONAL_CUTOFF` | 0.55 | single sine 0.984 / six-tone 0.945 vs broadband 0.018; band-limited noise 0.014–0.124 | one fixture set |
| `AMBIGUITY_RATIO` | 0.40 | runner-up at ≥40 % of the winner counts as a second alignment | judged |
| `MIN_ALIGNMENT_VOTES` | 200 | a window below this cannot pose as an independent alignment | judged |
| valley ratio (display grouping) | 0.85 | **display only** — `alignment_evidence()` decides on `raw_peaks`, not on the grouped list | judged |

### Known boundaries — state these, do not paper over them

- **1 % time stretch is not supported.** Drift reaches ~3 s at 300 s, far beyond
  ±0.192 s. The verdict is `insufficient_evidence`, which means *this method
  cannot align stretched material* — **not** "different audio".
- **`ambiguous_alignment` is not a negative.** It means the content repeats.
- **`same_audio_segment` proves a shared recording, never a shared file.** Stock
  music, dubbing, or one track reused in unrelated videos all match.

## 2. Image / frame comparison (`verify.py`)

| measure | accept | reject | measured |
|---|---|---|---|
| pixel delta | `YAVG < 1.0` and `Y_p99 < 12` | `YAVG > 6` | identical image at another size: 0.558 / 3.0. Different picture: 87.7 / 236 |
| frame fingerprint | `top_corr >= 0.85` **and** `modal_offset_votes >= 3` | otherwise | true pair 0.9315 with 4 votes at +25.5 s; unrelated pair 0.7417 with **0** votes |
| PSNR on aligned segment | `>= 30 dB` strong, `22–30` weak | `< 22` | aligned pair 20.1 dB; unrelated 11.9 dB |
| SIFT inliers | `>= 50` **and** `> 5 × max(negative)` | otherwise | identical 564; unrelated controls 25 and 11; plausible-but-wrong suspect 10 |

**Why the blur:** two identical images read `YMAX 33` before smoothing, because
cv2 `INTER_AREA` and ffmpeg `lanczos` leave single-pixel spikes. After a 5×5
Gaussian the same pair reads `Y_p99 = 3.0`. Use the 99th percentile, not the max.

**Why controls are mandatory:** the true original's channel card — same person,
same room, same outfit — scored 15 inliers against the target cover, *higher than
one genuine negative control*. Without a noise floor that reads as confirmation.

## 3. Reference case (the only end-to-end trace)

`b23.tv/kwoerN3` → `BV1TrxQ64EXo` (小哆吃不饱, 631 s) → `BV1cU5C68EEi`
(shao御, 662 s, 2026-05-13) → `PnAKqVB9PPo` (甘楽らむ, 723 s, 2026-03-07).

Plus a third re-upload found later: `BV1BuNgzREmz` (877 s, 2026-03-08).

**The 877 s copy is LATER than the 723 s master and still longer.** This is the
counterexample that killed the "longer = upstream" rule. Any future attempt to
reintroduce duration monotonicity should start here.

Discovery note from the same case: `page_size=50` surfaced a target at **rank 45
of 50** that was invisible at the default 20. Ranking is not coverage.

## 3b. Parallel discovery (`discover.py`)

Measured on the reference case `BV1p4KhzoEck`, 2026-11-05/06, budget 80 s /
100 requests. These are real network numbers, not fixtures.

| stage | candidates | bilibili | youtube | wall |
|---|---|---|---|---|
| before any name filter | 203 | 85 | 117 | 63 s |
| after `_is_creator_term` | 86 | 8 | 77 | 57 s |
| after the cross name-lead filter | 39 | 8 | 30 | 56 s |

What each filter removed, and why it was wrong before:

- **`音符`** (Douyin's own nickname) produced 60+ unrelated videos because the
  exemption was `any(kw in author)` and one uploader was literally called
  `音符是我的大米饭`. Replaced by author concentration: a creator's results are
  dominated by one author, genre vocabulary is not.
- **`柚子`** is a real handle fragment, but the cross route had no
  `_hit_mentions` test, so 77 unrelated YouTube videos came back. same_site had
  the test; cross did not.
- **`死亡底噪`** is genre vocabulary. Its hits are filtered by
  `_is_common_term`; the lead itself is kept, because a lead is a query.

The remaining 8 Bilibili candidates are all genuinely "蕾丝手套 / 搓麦" videos,
and the 30 YouTube ones all actually carry 柚子 in the title or channel.

### Numbers that are still guesses

| constant | value | basis |
|---|---|---|
| `CREATOR_SHARE` | 0.5 | one case; 甘楽 = 10/10, 死亡底噪 = 1/20 |
| `_is_common_term` threshold | >50 % of >= 8 hits | one case |
| `_hit_mentions` | substring match | no stemming, no variants |
| `Budget.ENRICH_RESERVE` | 2 | designed, not measured |
| `RateLimiter` default gap | 3.0 s, 6.0 s for bilibili | carried over from comments.py |

`CREATOR_SHARE` has exactly two data points and they are 1.0 and 0.05 apart.
Anything between 0.1 and 0.9 would fit both. It is a discriminator, not a
calibrated threshold.

## 4. What has never been tested

State this plainly in any report that leans on the numbers above:

- **No real recordings.** All audio fixtures are synthesised.
- **No cross-case set.** Every threshold comes from one case or one fixture family.
- **No online regression.** Endpoint behaviour is mocked in every test.
- **No real image pairs beyond the reference case.**

The honest claim is: *this implementation behaves as designed on the bundled
fixtures.* It is not a claim about field accuracy.
